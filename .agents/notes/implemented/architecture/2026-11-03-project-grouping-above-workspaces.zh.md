# Agent Note: 工作区之上的项目分组使用独立存储领域

Status: implemented

[English](2026-11-03-project-grouping-above-workspaces.md) | 中文

## 问题

侧边栏层级此前是工作区与会话：一条持久目录记录，以及在其中运行的会话。用户需要把工作区持久地分组为用户命名的分区，而工作区之上的这一层级同时决定多条约定。把分组存放到工作区记录上，会改变工作区领域的 schema，让一次成员变更变成跨领域的第二次写入并需要自己的对账，还要求工作区引导与排序路径携带分组状态。存放多对多关系则允许一个工作区出现在两个分区中，而产品需要恰好一个，并且仍须强制单归属不变量。项目还必须能在工作区注册被删除后存活，并且绝不删除工作区、目录或会话。

## 决策

项目是独立 `project` 存储领域（版本 1）中的持久实体：一个全局单例持有唯一的 `{ id, title, workspaceIds, createdAt, updatedAt }` 记录有序数组，没有表，初始为空。每次创建、重命名、删除或成员变更都一次写入替换该数组，并为 `project` 领域发出一次 `domain/changed` put，因此项目变更具有原子性，并在同一个提交点变得可见。数组顺序即显示顺序，新创建的在前。

工作区记录不携带项目 id。分组不进入工作区 schema、顺序、引导和待定变更路径，因此创建或删除工作区绝不写项目状态。成员资格存放在项目记录上，使工作区记录无论是否被分组都完全相同，并让注册表在唯一一条项目写入链上跨完整项目集强制单归属不变量。成员 id 对应的 Workspace 注册已不存在属于过期成员资格，而非损坏：`listProjects()` 与 `getProject()` 在投影中过滤它，下一次项目变更会从该次变更触碰到的记录中剪除它。重复项目 id、重复标题或把一个工作区声明在两个项目下的存储状态，启动时作为损坏大声失败。

标题在持久化边界上按精确字符串唯一，且必须非空；重复标题以 `ProjectTitleConflictError` 拒绝，空白标题以 `TypeError` 拒绝。`createProject(title)` 在最前面插入一个空项目，`renameProject(id, title)` 保留身份、顺序与成员，`deleteProject(id)` 移除记录并让其成员工作区变为未分组，`assignWorkspaceToProject(workspaceId, projectId?)` 把工作区追加到目标项目并在同一次写入中丢弃它在其他项目中的成员资格，省略目标时将其移出所有项目。这些操作都不会移动、重命名或删除工作区、目录或会话。

传输层保持相同的归属划分：`WorkspaceController` 获得四个仅限所有者的项目动词，follow 基线携带 `projects`，`{ type: 'projects' }` 增量发布变更后的列表；非所有者的项目只携带该调用方访问权限允许的成员工作区。客户端新增 `project` 分组模式，以项目分区与未分组分区呈现，并成为侧边栏默认模式。

## 考虑过的替代方案

**在工作区记录上加 `projectId` 字段。** 这把分组放进工作区领域 schema，使一次成员变更变成跨领域的两次写入——工作区记录与项目顺序——并需要为这一对写入新增待定变更对账路径。它还让每次工作区写入都携带不描述任何目录事实的分组状态，并改变从会话头部重建工作区的引导投影。

**以工作区 id 为键的成员关系连接表。** 这让多对多变得简单，却失去单归属强制：唯一性需要第二个索引或跨行不变量，而相同的用户变更可能违反它；成员显示顺序也需要自己的序号列，而不是一个数组。

**把成员资格作为有序数组存到工作区上。** 这样当产品要求每个工作区恰好一个分区时，一个工作区可以出现在多个项目中，而单归属规则仍须在多记录写入中跨所有受影响记录强制。

**从工作区路径派生项目。** 项目由用户命名且与目录无关。路径派生的分组无法命名任意工作区集合，无法把目录互不相关的工作区分到一组，也无法在重命名后保持稳定身份。

## 结果

项目变更是单次原子写入，工作区领域不受影响：没有 schema 版本升级，没有新的待定变更恢复路径，顺序与引导也不变。代价是一次跨领域读取投影：项目视图要对照现存工作区集合过滤成员 id，过期成员资格会留在存储中，直到后续项目变更剪除它触碰到的记录；该残留有界，且不会产生错误投影。单归属强制落在一条写入链上，因此两次并发分配会串行化，而不是产生属于两个项目的工作区。删除项目仍是单次写入，保留每个工作区、目录与会话，从而把「移除绝不删除数据」的保证延伸到新层级。

验证覆盖注册表（原子创建/重命名/删除/分配、单归属强制、过期 id 过滤与剪除、重复与空白标题、损坏已存状态的大声校验）、控制器与馈送（四个动词、项目错误码、基线与 `projects` 增量、访问过滤），以及客户端树与浏览器（项目模式、未分组分区、成员移动、持久化展开状态）。
